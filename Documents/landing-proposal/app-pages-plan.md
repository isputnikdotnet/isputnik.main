# App pages — plan

A page of its own for each application on isputnik.net, behind the "Everything on
board" table on the landing page. Draft 2026-11-15, for review.

## In one sentence

Eight pages, one per application, all cut from the same template and fed from one data
file, so the landing page's table and each app's page can never disagree.

## The pages

| Address | Application | Repo / container |
|---|---|---|
| `/audiobooks/` | Audiobooks | isputnik.home |
| `/ebooks/` | Ebooks | isputnik.home |
| `/photos/` | Photos & home video (incl. phone backup, faces) | isputnik.home + isputnik.faces |
| `/stories/` | Stories (recipes, reviews) | isputnik.home |
| `/family-tree/` | Family tree | isputnik.home |
| `/movies/` | Movies & TV | isputnik.video (add-on) |
| `/games/` | Family games | isputnik.games (add-on) |
| `/tv/` | iSputnik TV | isputnik.tv (Android TV / Fire TV) |

Short, plain addresses (`/movies/`, not `/isputnik-video/`): they are what people type
and share. The repo names appear on the page, not in the URL.

Not app pages, but the same mechanism, later: `/privacy/` (the full privacy story,
including the list of optional online lookups), `/news/` (posts + feed), `/download/`.

## What every app page has, top to bottom

1. **Hero** — app name, one-line promise, two or three sentences, the promise line
   (No cloud needed · No ads · No hidden costs · No tracking), one large screenshot.
   Add-ons say so in the eyebrow ("ADD-ON · RUNS BESIDE ISPUTNIK.HOME").
2. **What it does** — three or four groups of features, each a short heading, a sentence,
   and its bullets. The landing table shows the first five bullets; the page shows all.
3. **Screenshots** — a strip of three to five real captures, the same enlarge dialog as
   the landing page.
4. **Private here, specifically** — two or three facts true of *this* app, not the
   general promises. Examples:
   - Photos: faces found on your machine; phone backups go to a library only their owner
     opens; what the map and place names ask online (to check against the code before
     it is written).
   - Movies: your files, not a streaming service; film details use your own TMDB key;
     nothing is reported about what you watch.
   - Games: matches between your family on your server; a guest link opens one match,
     nothing else.
5. **Works with** — the other apps it connects to (a photo in a story, a person in the
   tree, a book in a quote), each linking to that app's page.
6. **What you need** — e.g. Movies: the video container, and for smooth conversion an
   Intel GPU or a recent CPU; TV: an Android TV or Fire TV device and a server reachable
   from it. Plain words, linking to the guide for details.
7. **Questions** — two to four questions about this app, taken from `docs/users/faq.md`
   and the app's guide.
8. **Get it** — the install card (home) or the add-on's card, the guide link, and
   previous / next app links along the bottom.

## How it is built

The site becomes a **Jekyll** site, which GitHub Pages builds by itself — no Actions, no
build step on our side, and `index.html` keeps working as plain HTML.

```
_config.yml              site title, URL, plugins: jekyll-feed, jekyll-seo-tag
_layouts/default.html    header, footer, the Orbit stylesheet — every page
_layouts/app.html        the app page template above
_data/apps.yml           ONE entry per app: slug, name, colour, tagline, add-on?,
                         feature groups, privacy facts, needs, screenshots, guide link
_apps/photos.md          front matter only (slug) + any free text for that app
...
index.html               the landing page; its features table loops over apps.yml
_posts/                  news posts (the News section and /feed.xml)
```

- **One source of truth:** `_data/apps.yml` feeds the landing table, each app page, and
  the previous/next links. Changing a feature is one edit.
- **Search and sharing:** `jekyll-seo-tag` gives every page its title, description and
  link-preview image; each app page uses its hero screenshot as the preview.
- **Navigation:** the top bar gets an **Apps** menu (the eight apps, with their colour
  dots) in place of **Explore**; on phones it is a list at the top of the menu.

## Order of work

1. **Mockup one page** — `/photos/` as static HTML in this proposal folder, using
   today's screenshots, to settle the template before anything else is written.
2. **The other seven** as mockups from the same template (copy only; screenshots
   reused or marked as missing). *Done 2026-11-15:* all eight pages are generated by
   `node build-app-pages.mjs` from `apps-data.mjs` — the stand-ins for
   `_layouts/app.html` and `_data/apps.yml`, so going live is a port, not a rewrite.
   Movies and Games show dashed "Screenshot to come" frames; TV uses the store
   captures (public-domain films) converted into `shots/`.
3. **Screenshots** — the Orbit re-capture (already planned) grows to cover every page:
   about 3–5 shots per app, ~30 in all; video, games and TV need captures from the
   demo site's public-domain films and a TV emulator.
4. **Go live** — convert to Jekyll (`_data/apps.yml`, layouts), replace the live
   landing page, add `/news/` and the feed, retire the old page.

## Open questions

- **Photos as one page or two?** Phone backup and face recognition are big enough to
  stand alone; proposed: sections of `/photos/` for now.
- **Russian versions?** The app speaks Russian; the site doesn't. Proposed: English
  first, `/ru/` later with the same data file carrying both languages.
- **Apps menu vs. Explore** — replacing Explore frees a slot in the crowded top bar.
